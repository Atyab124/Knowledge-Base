# Voice: Promoting My Work

Posts: 1 (TaskIt/CTO-framework), 3 ("Claude Ultra Code"), 7 ("Claude Code is sh*t."), 9a ("Most AI agent demos are sh*t.").

Read [../dos-and-donts.md](../dos-and-donts.md) first — this file only covers what's specific to this category.

## What this category is for

Prove something real got built and shipped. The audience is anyone deciding whether to trust your work — clients, collaborators, recruiters — and the entire mechanism is specificity: real numbers, real product names, real named people, an explicit line drawn around what the work is *not*.

## Shape

1. **Knock a bad pattern or a wrong assumption first**, then pivot into what you actually did:
   - *"Most AI agent demos are sh*t. ... So heres what im doing instead."* (9a)
   - *"Claude Code is sh*t. The LLM is excellent. The context management is the problem. ... So heres what im building instead."* (7)
   - *"Close followers of my Production Framework assumed Claude UltraCode just killed what im building. It didnt."* (3)
   - Post 1 is the exception — it opens on a broad industry question rather than a knock, then pivots the same way: *"Then I used it to build something real."*
2. **Specific, checkable numbers as the core evidence** — never adjectives. "~150 users," "73 active projects," "1,100 open tasks," "97% vs 14%." If a number isn't real yet, don't round one up.
3. **Name the product and say what it does in one plain sentence** — no marketing adjectives: *"TaskIt is a project and task management platform... in the class of Asana or Monday.com."*
4. **Draw an explicit boundary around scope** — precision about what the work is *not* is itself a credibility move: *"It doesnt decide how a team of agents works together inside a company... Thats not a deployment problem. Thats an org problem."* (3); *"Neither for sale yet."* (9a).
5. **Close on the signature line or an ownership statement.** *"Not a screenshot."* closes 3, 7, and the anecdote in 9a — reuse it verbatim, don't rephrase it. Post 1 closes differently, on a line that claims the judgment calls stayed human: *"I rule on every design, read every database change before production, and test each release myself."* Use that variant when the point is "automation, not abdication."
6. **A real named person as endorsement-by-association, when one is available**: *"I work directly with one of them. Ajay Mankani. Hardest worker in our entire org, day in day out."*

## Register

Short, punchy, declarative sentences. Heavy one-line paragraphs. Post 1 uses `→` arrows to itemize the three findings — reach for that only when listing parallel discrete findings, not for general emphasis. Contractions frequently drop the apostrophe (didnt, doesnt, dont, im) in 3, 7, and 9a; post 1 is the most polished of the four and keeps full punctuation — match the register to how "finished" the underlying result is, rougher for a fresh build update, cleaner for the flagship case study.

## Checklist

- Is every number in the post real and specific, not rounded up or invented?
- Does the post state what the work explicitly does *not* do or is *not* (yet)?
- Does it end on "Not a screenshot." or an equivalent ownership line — not a generic "excited to share"?
- If a real person is named, do they get one earned, concrete credential — not just a title?
